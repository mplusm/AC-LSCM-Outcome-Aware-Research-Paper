\begin{abstract}
Agents that act on real systems should predict what their actions will cause
before acting. We study when causal structure helps a learned forward model do
this, using a planner that rejects candidate actions whose simulated
multi-step outcome is unsafe, in synthetic structural causal models where the
true consequences are known. We compare the Action-Conditioned Latent
Structural Causal Model (AC-LSCM: per-factor mechanisms over a learned sparse
graph, actions as do-interventions) with three unstructured forward models on
seven random graphs with 10 or 20 variables, a task configured by a fixed
rule, and two controls: a do-wrapper that gives every model the same action
semantics, and counterfactual data given to all models or to none. When its
factors are the observed variables, AC-LSCM recovers the true graph exactly
on every 10-variable graph and has lower three-step prediction error than
every baseline in all 396 paired comparisons. Its excess safety violations
over an oracle are 0.25 of the no-model level on 10-variable graphs (best
baseline 0.31) and 0.41 on 20-variable graphs (0.53), and its margin is
largest for two-variable actions never seen in training (0.18 versus 0.28).
With learned latent factors the same model is worse than the baselines; the
choice of factors matters more than the explicit do-operator or
counterfactual data, and every planner stays far from the oracle. This
version corrects an earlier one, whose model learned an empty graph and whose
headline 36$\times$ safety improvement came from a task that tested only
extrapolation of action values; we withdraw that claim. Code and all
per-seed results are released.
\end{abstract}

\noindent\textbf{Keywords:} agents, world models, structural causal models,
causal dynamics, safe action selection, counterfactuals.


\section{Introduction}

Consider a code agent that generates and executes a database migration. The
migration is syntactically valid, matches the user's request, and silently
drops a foreign-key constraint that downstream services depend on. The harm is
not in the action itself but in what it causes one or two steps later. An
agent that is to avoid such outcomes needs a \emph{forward model}: something
that predicts, before execution, the state a candidate action will lead to,
including its indirect effects, so that the action can be rejected or the
decision deferred.

Language-model agents mostly lack such a model. Their training objective is
next-token prediction, and current models perform poorly on formal
interventional and counterfactual queries~\citep{jin2023cladder,chen2025counterbench}.
Recent agents obtain a forward model by prompting the language model to
simulate outcomes~\citep{hao2023rap,gu2024webdreamer,ruan2024toolemu}. A
natural alternative, long studied in model-based reinforcement learning, is a
learned world model~\citep{ha2018world,hafner2019planet,hafner2023dreamerv3}.
Causal reasoning suggests a specific inductive bias for such a model: a state
made of variables, one mechanism per variable over a sparse set of causes,
and actions that replace mechanisms rather than enter as generic
inputs~\citep{pearl2009causality,scholkopf2021causal}. Whether that bias
actually makes an agent safer, and which part of it matters, is an empirical
question, and it is the question of this paper.

We study it where the answer can be checked: synthetic structural causal
models (SCMs) with known graphs, mechanisms, and noise, so that the realized
consequence of every candidate action is available. A planner simulates each
candidate with a learned forward model, discards candidates whose predicted
trajectory violates a safety predicate on a variable downstream of the
intervened one, and defers if none remain. We compare the Action-Conditioned
Latent Structural Causal Model (AC-LSCM) with three unstructured forward
models under the same planner.

\paragraph{What changed from the first version.}
An earlier version of this work~\citep{madapathi2026zenodo} reported that
AC-LSCM reduced safety violations $36\times$ relative to a Transformer. That
result does not hold. The model as specified there learned an empty causal
graph in every run, and the agent task only tested whether a model knows that
$\doop(z^i = v)$ sets $z^i$ to $v$, with unsafe values outside the training
range; the Transformer's failures there were failures to extrapolate.
Section~\ref{sec:v1} documents both problems and we withdraw the claim. The
study reported here replaces the first version's experiments.

\paragraph{Contributions.}
\begin{enumerate}
\item \emph{A controlled protocol for consequence-aware planning.} Seven
random SCMs with 10 or 20 variables; a consequence task whose safety and goal
variables and thresholds are chosen by a fixed rule; an oracle and a no-model
reference per environment, used to normalize violation rates; actions on two
variables at once, which never occur in training; a \emph{do-wrapper} that
gives every forward model the same, correct action semantics, so that the
effect of how a model represents actions can be separated from the quality
of its dynamics; and counterfactual training data given either to every
model or to none (Section~\ref{sec:setup}).
\item \emph{A positive result for causal structure over the right
variables.} With the observed variables as its factors, AC-LSCM recovers the
true graph exactly on all five 10-variable graphs, has lower three-step
prediction error than every baseline in all 396 paired comparisons, and has
the lowest normalized safety violations of all planners, with the largest
margins on 20-variable graphs and on unseen two-variable actions
(Section~\ref{sec:main}).
\item \emph{Negative and null results that locate the benefit.} With learned
latent factors the same architecture is worse than the baselines, because an
intervention on a latent coordinate does not correspond to the intended
intervention on the observed variable. Given correct action semantics, an
explicit do-operator adds little; sparsity helps on 20-variable graphs;
counterfactual training data helps the factored model only on 20-variable
graphs and the baselines not at all; and every planner remains well short of
the oracle (Sections~\ref{sec:latent}--\ref{sec:ablations}).
\item \emph{A correction of the first version} (Section~\ref{sec:v1}).
\end{enumerate}

\paragraph{Scope.}
All environments are synthetic and low-dimensional, with lagged
additive-noise mechanisms and observations that are a noisy copy of the
state. We do not evaluate language models or text-based tasks.
Section~\ref{sec:limitations} states what the evidence does and does not
establish.

\section{Background: Interventions and Forward Models}
\label{sec:background}

Pearl~\citep{pearl2009causality} distinguishes association, $P(y \mid x)$;
intervention, $P(y \mid \doop(x))$, the distribution when $x$ is set by an
external agent; and counterfactuals, $P(y_x \mid x', y')$, what would have
happened in a specific realized case under a different action. A forward
model for planning has to answer interventional queries: if I take this
action in this state, what will the state be over the next few steps?

Two remarks frame what causal structure can add. First, when the agent
conditions on its own action and on the full state, and nothing unobserved
drives both the action and the outcome, the conditional and interventional
distributions coincide. A generic action-conditioned model trained on
logged interactions can therefore learn the right interventional
distribution without any causal machinery, given enough data that covers the
relevant actions and states. Second, what a structural model adds is
\emph{modularity}. If each variable has its own mechanism over a small set of
causes, and an action replaces exactly the mechanism of the variable it
targets, then the effect of a new combination of interventions can be
predicted by composing mechanisms that were each learned from other data.
This predicts that structure should help most where data are scarce relative
to the size of the system and where the agent considers actions unlike those
in its training data. The experiments test these predictions.

\section{AC-LSCM and the Planner}
\label{sec:arch}

\subsection{Structural transitions}
The state is a vector of $K$ factors $\z_t = (z_t^1, \dots, z_t^K)$ with
scalar $z_t^i$. Each factor has its own mechanism, a small neural network
$f_i$:
\begin{equation}
  z_{t+1}^i := f_i\big(A_{i,:} \odot \z_t\big) + \epsilon_t^i,
  \qquad i \in \{1,\dots,K\},
  \label{eq:sem}
\end{equation}
where $A \in \{0,1\}^{K\times K}$ is a learned adjacency matrix ($A_{ij} = 1$
if $z^j_t$ is a parent of $z^i_{t+1}$) and $\epsilon_t^i$ is exogenous noise.
Parents are taken at time $t$ and children at $t+1$, so the unrolled graph is
acyclic for every $A$ and no acyclicity constraint is needed. $A$ is
parameterized by logits $\Theta$ initialized at $+2$ (a dense graph). During
training we sample $A$ with a hard Gumbel-sigmoid and a straight-through
gradient, so that training and evaluation use the same kind of binary mask;
at evaluation $A_{ij} = \mathbf{1}[\sigma(\Theta_{ij}) > 0.5]$.

\paragraph{Actions as interventions.}
An action $a_t$ sets a subset of factors to given values. Under the
\emph{hard do-operator}, an intervened factor takes its value exactly,
$z_{t+1}^i := a_t^i$, and its mechanism is not evaluated; all other factors
follow Equation~\eqref{eq:sem}. The intervention reaches other factors only
through the graph, from the next step on. A \emph{soft} variant, used in the
first version, instead passes $a_t^i$ to $f_i$ with the parents masked out
and relies on $f_i$ learning to output it.

\subsection{Two choices of factors}
\emph{Latent AC-LSCM.} An encoder maps the observation $\x_t$ to latent
factors $\z_t$ and a decoder maps them back, as in latent world
models~\citep{hafner2019planet}. An action on observed variable $i$ is
applied to latent factor $i$. Nothing forces latent factor $i$ to be observed
variable $i$, so this relies on training to align them.

\emph{Factored AC-LSCM.} The factors are the observed variables themselves,
$\z_t = \x_t$, with no encoder or decoder. This is the natural choice when the
agent observes the variables its actions and predicates refer to, as in our
environments and in many structured agent settings (fields of a database,
service health metrics, configuration values), and it is the setting of work
on causal dynamics models in reinforcement learning~\citep{wang2022cdl,pitis2020coda}.

\subsection{Training objective}
Both variants minimize
\begin{equation}
  \mathcal{L} = \big\|\x_{t+1} - \hat\x_{t+1}\big\|_2^2
  + \mathcal{L}_{\text{trans}} + \tfrac12 \lambda_1 \|A\|_1
  + \beta_{\text{cf}}\, \mathcal{L}_{\text{cf}},
\end{equation}
where $\hat\x_{t+1}$ is the decoded one-step prediction under the logged
action, $\mathcal{L}_{\text{trans}}$ is the Gaussian KL term between the
encoder posterior of $\x_{t+1}$ and the predicted next latent (for the
factored model it reduces to a squared error), and $\lambda_1 = 0.01$
(the \emph{dense} variants use $\lambda_1 = 0$). The weight of the sparsity
term is ramped up over the first 50 epochs.

The counterfactual term $\mathcal{L}_{\text{cf}}$ uses training transitions
paired with the outcome under a different action and the same noise. The
model predicts the counterfactual by abduction, intervention, and prediction:
it recovers the noise as the residual
$\hat\epsilon_t = \mathrm{enc}(\x_{t+1}) - \bar f(\mathrm{enc}(\x_t), \doop(a_t))$,
applies the alternative action $\tilde a_t$, and adds the recovered noise back
to every factor that neither action intervenes on. We consider three regimes:
\emph{none} ($\beta_{\text{cf}} = 0$, the default); \emph{observed}, in which
$\mathcal{L}_{\text{cf}}$ is the squared error against the observed
counterfactual outcome $\tilde\x_{t+1}$, and every model in the comparison,
including the baselines, receives the same pairs; and \emph{true latents},
the first version's regime, in which AC-LSCM alone is supervised with the
noise-free counterfactual state. The last regime gives AC-LSCM the true state
coordinates and is reported only for continuity.

\subsection{Outcome-aware planning}
\label{sec:planning}

Algorithm~\ref{alg:planning} uses a forward model to choose among candidate
actions. Each candidate is simulated for $H$ steps (the action at the first
step, no action afterwards). Candidates whose predicted trajectory violates
the safety predicate at any step are discarded; if none remain, the agent
defers. Among the rest it picks the candidate with the highest predicted goal
value, with a bonus for satisfying the goal predicate. Predicates are always
evaluated on predicted \emph{observations}, the one space all models share.

\paragraph{The do-wrapper.}
For a model that treats actions as generic inputs, we also run the planner
with a \emph{do-wrapper} that imposes the correct action semantics from
outside: predict the next observation with no action, overwrite the
intervened variables with their values, and continue the rollout with no
action. Because interventions in our environments act on the next state and
reach other variables only through the dynamics, the do-wrapper is exactly
right for any model, and it requires knowing only which variables an action
sets. Comparing each model with and without the do-wrapper separates errors in
action handling from errors in the learned dynamics. For the factored
AC-LSCM the two coincide.

\begin{algorithm}[t]
\caption{Outcome-aware action selection}
\label{alg:planning}
\begin{algorithmic}[1]
\Require observation $\x_t$, candidates $\mathcal{A}_t$, horizon $H$,
forward model $M$, safety predicate $S$, goal predicate $G$, goal value $V$
\State $\mathcal{C} \gets \emptyset$
\For{each $a \in \mathcal{A}_t$}
  \State $\hat\x^{(a)}_{t+1} \gets M(\x_t, a)$; \quad
         $\hat\x^{(a)}_{t+k} \gets M(\hat\x^{(a)}_{t+k-1}, \varnothing)$ for $k = 2,\dots,H$
  \If{$S(\hat\x^{(a)}_{t+k})$ holds for all $k \le H$}
     \State $\mathcal{C} \gets \mathcal{C} \cup \{a\}$
  \EndIf
\EndFor
\If{$\mathcal{C} = \emptyset$} \State \Return \textsc{Defer} \EndIf
\State \Return $\arg\max_{a \in \mathcal{C}}\ \big[ v_a + \mathbf{1}[G \text{ holds for some } \hat\x^{(a)}_{t+k}] \big]$,
       \ where $v_a = \max_k V(\hat\x^{(a)}_{t+k})$
\end{algorithmic}
\end{algorithm}
